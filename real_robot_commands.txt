5. TERMINAL 4 - LIVE PLOT USING THE SAME FOXY RUNTIME

Close the old Jazzy laptop plot and any laptop Gazebo nodes using domain 14.
FROM YOUR COMPUTER:

export ROS_DOMAIN_ID=14
ros2 daemon stop
ssh -X bingda@192.168.1.214

INSIDE THAT SSH SESSION:

source /opt/ros/foxy/setup.bash

cd ~/Downloads/rb2301_fp_10

python3 visualization/live_map.py --robot 14

The Python/ROS process runs on the robot. SSH forwards its window to your
computer. X11 forwarding and a graphical Matplotlib backend must be available;
if DISPLAY is empty or no graphical backend is found, fix that environment first.

DEFAULT PLOT: current LiDAR hits, regions, scores, carrot, command and scan ages.
Coordinates are relative to the robot now. It does not draw an invented global
map, movement history or route without position measurements. Actual movement
is labelled unmeasured. Case marks are recorded with timestamps, not locations.

OPTIONAL ROUTE PLOT: only if the base publishes valid /odom messages, run:

python3 visualization/live_map.py --robot 14 --pose-source odom

This uses wheel odometry instead of Optitrack. If /odom is unavailable, use the
default local view. Do not assume that /odom exists on the physical robot.

Plot keys: 1 = mark gap stop; 2 = mark unwanted U-turn; m = mark other case;
f = follow/whole view; q = save and close. Closing the plot does not stop the car.
Logs are saved on the robot in ~/Downloads/rb2301_fp_10/visualization/runs/.

DIAGNOSTICS - IN A FOXY ROBOT TERMINAL USING DOMAIN 14

ros2 topic info /scan
ros2 topic echo /scan sensor_msgs/msg/LaserScan --no-arr

Stop echo with Ctrl+C. These commands use Foxy syntax.

The viewer's default LiDAR x offset is 0.11423 m and hardware yaw is 0 degrees,
matching the controller's current assumptions, not a verified measurement.
After measuring the mount, override the viewer with --lidar-x VALUE --lidar-y
VALUE --lidar-yaw-deg VALUE and make navigation use the same verified transform.
